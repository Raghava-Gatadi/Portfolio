AppSec Assistant

A better starting point for manual code review.

Python 3.11+AST analysisHTML / JSON / SARIF
Explore the repository ↗

The problem

A source repository has far more code than an analyst can read at once. I built AppSec Assistant to map entry points, request inputs, sensitive APIs, and function scopes into a useful starting queue for manual review.

The tool runs locally and offline, without runtime dependencies or external services. It analyzes target code without importing or executing it.

Follow the data, keep the evidence

The Python analyzer uses the abstract syntax tree to follow request input through bounded, same-file helper calls to sensitive operations. It tracks argument binding, helper return values, and selected mitigation patterns, while retaining an explanatory trace with the finding.

Built for an analyst, not an automatic verdict

Reports include searchable, self-contained HTML plus text, JSON, and SARIF outputs. Findings carry evidence, CWE mappings, remediation guidance, and verification questions. A deterministic triage rank supports reading order; it is not CVSS or an exploitability probability.

The tool also includes approximate JavaScript/TypeScript checks and navigation maps for other backend languages. Dependency inventories describe packages; they do not perform vulnerability-advisory lookups.

Engineering choices

  • Explicit depth and work budgets: unsupported resolution and exhausted analysis can mark scans incomplete.
  • Reasoned suppressions, stable fingerprints, and reviewed baselines for repeatable review workflows.
  • Secret values and raw source snippets are omitted from reports; report metadata is escaped.
  • Target files are analyzed statically, with exclusions for generated and vendored code.

Validation and honest boundaries

The v0.2.0 release record documents 110 passing local unit tests and a published 28-case synthetic Python call-flow evaluation. The evaluation separates development and reserved cases and records misses and false positives. Those results are specific to the fixtures; they do not establish production-scale accuracy or performance.

Python helper analysis is bounded and same-file. Cross-file resolution, general object dispatch, callbacks, and general sanitizer correctness are outside the model. JavaScript/TypeScript analysis is approximate. Every finding still needs manual validation.

What I want the tool to do: help an analyst decide where to look next, understand why a path deserves attention, and carry useful evidence into the review.
